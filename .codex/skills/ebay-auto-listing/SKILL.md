# eBay Manual Listing Draft

Build a self-contained folder and copy-ready draft that the user can manually upload to eBay. Do not require an eBay Developer account or OAuth.

Treat the local product record, its exact product directory, original photos, inventory, and saved pricing as authoritative. Read `references/local-api.md` before resolving a product or its files. Read `references/ebay-workflow.md` before preparing images or listing copy.

## Workflow

1. Resolve the named product to exactly one local product. Ask only when multiple records remain ambiguous.
2. Load its full record, exact product directory, all original photos, inventory by location, and saved price.
3. Create a draft output subfolder inside the product directory so originals remain untouched.
4. Inspect every source photo before editing. Reject unrelated, duplicate, corrupt, or unusably blurred files. Prefer real photos where no card, label card, backing card, price card, or packaging card appears behind the product. When equivalent card-free photos exist, do not select card-backed photos for processing or as image-generation references.
5. Produce square marketplace images on a genuinely white background. Replacing or extracting the original background is required when it is gray, off-white, textured, shadowed, or visibly bounded; adding white canvas padding around an unchanged photo does **not** count as white-background processing. Start from the strongest card-free source whenever possible. Preserve the real product's shape, color, texture, markings, wear, count, arrangement, and included parts. Background removal is not permission to move, rotate, straighten, regroup, or respacing the photographed pieces. If a source shows repeated pieces arranged in rows or matched pairs, preserve those exact positions and natural imperfections; do not make them more uniform. If another source shows them loose or scattered, preserve that scattered layout. Preserve the exact verified selling-unit count and assortment; do not add or remove pieces except to correct a photographed overcount to the verified included count. Visually confirm that no item is duplicated, clipped, or obscured.
6. For repeated loose-piece products, the real-photo set must include all available views of these types: (a) one complete arranged/pair-layout image with only the background replaced, while keeping the source arrangement unchanged; (b) one complete loose/scattered image with only the background replaced, while keeping the source positions unchanged; and (c) one useful hand-for-scale/reference image. When a source contains a hand, retain the hand, its contact with the products, and the product positions, and replace only the surrounding backdrop with seamless white. Do not remove or reshape the hand automatically. If one of these source view types was not photographed, state that it is unavailable instead of fabricating it.

   For the hand-for-scale image, use this editing prompt, substituting only product-specific nouns when needed:

   > Edit the supplied real product photo into a square marketplace hand-scale image. Precisely segment and retain the original hand and every photographed product piece, including the natural skin texture, finger anatomy, overlaps, contact points, exact product designs, count, orientations, and relative positions. Remove the tabletop and all background texture completely, replacing it edge-to-edge with seamless pure white (#FFFFFF). Crop and reframe closely so the hand and products fill most of the square, allowing the hand or wrist to enter naturally from the left or lower edge. Do not leave the original rectangular photo, gray cast, paper texture, padding seam, large unused margins, or border. Do not redraw, beautify, reshape, move, straighten, regroup, duplicate, remove, or invent the hand or products. Preserve realistic edges and contact shadows only; add no text, props, graphics, or extra objects.

   Reject the result if it merely places the original photo on a white square, leaves a gray/off-white tabletop, creates white sidebars, shrinks the subject excessively, changes anatomy, or rearranges any piece.
7. Select the strongest card-free real product-only image as the main image. Never use an AI-generated scene as the main image. Never use a photo with a card behind the product as the main image when a usable card-free view exists.
8. Do not create a single-item size infographic for eBay. Keep verified dimensions in the listing copy and item specifics instead.
9. Generate exactly two additional reference-based lifestyle/use-context images from the real product photos. Use the `imagegen` skill and provide the strongest card-free source images as references. Keep the product visually faithful and label these files as generated reference images. These must be eBay-specific assets created for the current eBay draft. Never copy, hard-link, or reuse either generated image from a Walmart or other marketplace draft for the same product. Before delivery, compare filenames and SHA-256 hashes against sibling marketplace draft folders; any identical file is a failure and must be regenerated with a materially different, still-supported scene and composition.
10. Derive copy only from the product record, images, and user-provided evidence. Do not infer uncertain brand, material, measurements, compatibility, model, or included accessories as fact. For this seller's eBay drafts, default the condition to **New** with numeric Condition ID **1000** when the chosen category supports it, unless the product record, photos, or user says otherwise; flag contrary evidence for review.
11. Keep the title within 80 characters and front-load the strongest verified search terms.
12. Read the eBay **Retail price** from the resolved product's **Marketplace listings** section and use that saved value as the listing price whenever it is greater than zero. Treat this field as the authoritative price because it contains the user's accepted result from **Calculate price**. Record the product page and saved eBay listing record as the price source; do not replace the saved price by independently rerunning or reproducing the formula. The Markdown and CSV must use the same saved Retail price. If the eBay Retail price is missing or zero, run the website's **Calculate price** action for eBay, save the result back to Marketplace listings, then reread and use the saved Retail price. If neither a valid saved price nor a successful calculation is available, mark pricing incomplete instead of inventing a value.
13. Produce a complete copy-ready draft and a numbered image-upload order. Save the draft as UTF-8 Markdown in the output folder. Retain two opening prose paragraphs, then use the evidence-driven Package Includes, Size & Material, Features, and Wide Applications structure defined in `references/ebay-workflow.md`.
14. At the same time, create `ebay-draft-upload.csv` from `assets/eBay-draft-listing-template-US.csv`. Preserve its four `#INFO` rows and exact official header. Replace the sample row with exactly one row for the resolved product. Set `Custom label (SKU)` to the resolved product's exact local inventory number, such as `INV-76`; do not put the product SKU, Actual SKU, UUID, or product other identifier in that CSV field. Keep the product's own SKU separately in the Markdown identity/audit. Read the CSV rules in `references/ebay-workflow.md` before populating it.
15. Reopen and visually inspect every processed and generated image, not only the sources. Confirm the two generated eBay scenes are materially different from all Walmart-generated scenes for the same product, not merely renamed, resized, recompressed, color-shifted, or lightly recropped versions. A completed white-background image must have no visible gray/off-white rectangle, original backdrop boundary, room surface, or padding seam around the subject. Compare each processed real image against its source and confirm the original arranged, scattered, or hand-held composition was not reorganized, while the exact count and assortment remain correct. Run `scripts/validate_marketplace_images.py` on the processed real images; for the intentional hand-for-scale photo use its supported hand/border exception when appropriate. Treat pixel checks as a minimum screen, not a substitute for visual inspection. If either check fails, redo the background before delivery.
16. Validate that the CSV has the unchanged 11-column header, one product row, valid CSV quoting, `Action=Draft`, the exact `INV-xx` value in `Custom label (SKU)`, and UTF-8 encoding. The Markdown and CSV values for title, price, quantity, custom label, condition, and description must agree; the local product SKU remains a separate Markdown field.
17. Return the output folder, Markdown draft, and uploadable CSV to the user. Do not attempt API publishing.

## Safety Boundaries

- Never overwrite or destructively edit original product photos.
- Never change the actual product, hide defects, fabricate labels, add accessories, or make generated images imply unsupported features.
- Never claim that an AI-generated image is a real photograph. Keep the two generated reference files distinguishable in filenames and in the draft manifest.
- Never mix images or facts from another SKU. Verify the product identity before producing outputs.
- Do not treat a removable card behind the product as part of the product. Use a card-backed photo only when no usable card-free source exists or when the card is genuinely included with the item; keep it secondary and state the uncertainty if inclusion is unclear.
- Never claim the category or item specifics are certain when the available evidence is insufficient; mark uncertain fields for manual confirmation.
- Never attempt to log in to eBay, publish, or revise a live listing in this manual workflow.
- Treat the bundled CSV as an eBay US Seller Hub Draft upload template. Do not silently invent a Category ID, UPC, or Condition ID. If a required coded value cannot be supported, leave it blank when eBay permits that or mark the package not upload-ready and identify what the user must confirm.

## Output

Return: readiness summary; product identity and source directory; output directory; Markdown draft; Seller Hub Draft CSV; numbered image list distinguishing edited real photos and two generated reference images; title; category suggestion; condition; item specifics; description; price; quantity; local product SKU; `INV-xx` eBay custom label; shipping and return notes; unresolved fields; and concise upload instructions.
